# Перенос проекта JasPulse на другой компьютер / сервер

## 0. Карта проекта — что где лежит

### 🕷 Парсер / сбор данных
| Файл | Роль |
|---|---|
| `almaty_monitor.py` | **ЯДРО скрапера Threads** (Playwright, DOM-парсинг постов) |
| `run_hourly.py` | **Раннер по расписанию** (раз в час): сбор → `output/threads_live.json` → зовёт деплой |
| `threads_login.py` | Одноразовый вход в Threads → сохраняет сессию в `auth_state.json` |
| `citizen_voice.py` + `comment_insights.py` | Сбор реплаев + «Мнения жителей» (локальный/облачный ИИ) |
| `ingest_meta.py` | Приём CSV-выгрузок Meta Content Library (FB/IG) |

### 🎨 Дизайн / дашборд
| Файл | Роль |
|---|---|
| `dashboard_template.py` | **ВЕСЬ дизайн дашборда** (HTML/CSS/JS): сайдбар, переключатель Город/Молодёжь, командный центр, карта, мнения жителей |
| `build_dashboard.py` | Собирает из шаблона → `public/index.html` (город) и `public/ump.html` (УМП/молодёжь) |
| `merge_and_deploy.py` | Мёрж Threads+Meta → пересборка → деплой на Vercel |
| `refresh.py` | Обновить всё одной командой (ingest → AI → build → deploy) |
| `citypulse/index.html` | ОТДЕЛЬНЫЙ лендинг-визитка, **это НЕ дашборд** |

### 🔒 Что НЕ в git (переносится вручную, лежит в `state.tgz`)
- `.env` — все ключи (Groq/Vercel/Redis, THREADS_COOKIE)
- `auth_state.json` — сессия Threads
- `data/` — `meta_clean.json` (корпус FB/IG) + кэши ИИ (`grok_cache.json`, `ump_cache.json`)

## Какой дизайн «настоящий»
Актуальный дашборд **собирается из `dashboard_template.py`** и живёт на Vercel:
`public-jade-one-257.vercel.app` (город) + `/ump` (молодёжь/УМП). Готового HTML в git нет —
он генерируется командой `build_dashboard.py`. Не путать с `citypulse/index.html` (это лендинг).

## ✅ Что нужно поднять для КОРРЕКТНОЙ работы
1. **Код** — `git clone`
2. **Секреты** — `.env` + `auth_state.json` (из `state.tgz`)
3. **Данные** — `data/` (из `state.tgz`)
4. **Окружение** — Python 3 + venv + `requirements.txt` + Playwright Chromium; **Node.js** (для деплоя Vercel)
5. **ИИ** — доступ к модели: облачный **Groq** (по `.env`) ИЛИ внутренняя Qwen (если в той же сети). Проверь `LLM_BASE_URL` / `LLM_MODEL` / ключ в `.env`
6. **Расписание** — раз в час: Task Scheduler (Windows) или systemd-timer (Linux)

## Пошагово

### На СТАРОМ компе (уже сделано)
- Задача `AlmatyHourlyScraper` **отключена** ✅
- Собран `state.tgz` (секреты+данные) → скопируй на **USB** (внутри ключи — не в облако/почту)

### Вариант A — другой Windows-комп
1. Установи **Python 3.12** (python.org, галка «Add to PATH»)
2. `git clone git@github.com:qoparu/Threads-Scraper.git` (нужен SSH-ключ в GitHub)
3. Распакуй `state.tgz` в папку проекта (положит `.env`, `auth_state.json`, `data/`)
4. `python -m venv venv`
   `venv\Scripts\pip install -r requirements.txt`
   `venv\Scripts\python -m playwright install chromium`
5. Тест одного прогона: `venv\Scripts\python run_hourly.py`
6. Расписание: `powershell -ExecutionPolicy Bypass -File register_hourly.ps1`
   ⚠️ Если это ноут, который выключают — проблема «зависит от компа» останется. Для 24/7 → сервер.

### Вариант B — Linux-сервер / VPS (рекомендую для 24/7)
1. `git clone …` на сервере
2. Скопируй `state.tgz` (scp) → `tar xzf state.tgz`
3. `bash deploy/setup.sh` — поставит окружение + systemd-таймер раз в час
4. Проверка: `sudo systemctl start jaspulse.service`
   Подробно — `deploy/DEPLOY_SERVER.md`

## Проверка, что всё работает
- Прогон `run_hourly.py` завершается без ошибок
- В подвале дашборда статус «Сбор данных 24/7» **зелёный**, время обновилось
- Дашборд на Vercel пересобрался

## Безопасность
- Секреты только вручную (USB/scp) — **не через git/почту/чат**
- **Смени** Groq-ключ и Vercel-токен, что светились в чате
- Репозиторий держи **приватным**
- `state.tgz` после переноса **удали** с носителя
